## 1. Исходники и контекст

- Концепт v3: `docs/FEATLY_v3_CONCEPT.md` (все шаги 0–6 ✅)
- Аудит Kimi K2.6 Fast: `docs/legacy/featly_v3_audit.md` (разбор ревьюера — в тексте этого файла)
- Текущие авторы ключей: плагин = hub API через `X-API-Key` — **сейчас плагин ключ НЕ шлёт (блокер!)**

### Критичные решения, уже принятые (не менять при разработке)

1. **«Имя персонажа» на FunPay — обязательное поле** (категория «Предметы», контролируется площадкой).
   → Источник ника для выдачи — `Order.player` из полного заказа (`account.get_order(id)`).
2. **Три режима ника** (`nickname_source`):
   - `auto` — берём из `order.player`, подтверждаем «Да»;
   - `auto_trusted` — берём из `order.player` **без подтверждения**, если ник найден в Roblox 1-в-1; иначе подтверждаем;
   - `ask` — всегда запрашиваем с нуля (резерв).
3. **Запрос в друзья — вкл/выкл** (`add_friends`). Отключение не отменяет подтверждение ника
   (ник нужен для матчинга выдачи, а не для заявки).
4. Опасные для «настройка из TG» поля (api_key/ws_secret/database_url) — **только чтение** в панели
   (без самоотрезания); machine-конфиги (systemd/docker) — вне панели.
5. Retry к hub — **только для идемпотентных** запросов (GET/статусы/отмена); POST-создание без retry
   (уникальность закрыта `funpay_order_id` на стороне hub).

## Эшелон C — умная автовыдача (опросные решения)

| # | Задача | Детали |
|---|---|---|
| C1 | `settings.py`: `add_friends: bool=True`, `nickname_source: "auto"\|"ask"\|"auto_trusted"` | кэш в `settings.json` |
| C2 | `order_manager.handle_new_order`: `order_full = account.get_order(order.id)`; `nick = order_full.player`; выбор шага диалога | шаг диалога: `confirm_nick` (ник предзаполнен) или `waiting_nickname` |
| C3 | Шаг `confirming`/`confirm_nick`: ветка `add_friends` — skip `request_friendship`, если выкл | лог причины |
| C4 | Режим `auto_trusted`: `validate_username(nick)` exact-матч и без «Верно?» идемпотентно финализировать диалог | иначе → подтверждение |
| C5 | Панель: экран «🚀 Настройки выдачи» (toggle add_friends, цикл nickname_source) | без FSM-ввода — callback-циклы |
| C6 | Hub: без изменений (ник в `orders.buyer_nickname` уже есть; `!смена` готов) | путь «▼ смена» не трогаем |

### Потоки диалога (тесты руками)

| nickname | player заполнен | add_friends | Итог |
|---|---|---|---|
| `auto` | да | вкл | «Ник: X. Верно?» → Да → заявка → заказ → сервер/трейд |
| `auto` | да | выкл | «Ник: X. Верно?» → Да → заказ → сервер/трейд (без заявки) |
| `auto` | нет | — | «Напиши ник» как сейчас |
| `auto_trusted` | да, найден 1-1 | — | сразу заказ → сервер/трейд (без вопросов) |
| `auto_trusted` | да, не найден | — | «Ник: X. Верно?» (подтверждение) |
| `ask` | — | — | всегда запрос + подтверждение |
| любой | — | !смена | подтверждение → `PATCH /orders/{id}/nickname` (уже готово) |
